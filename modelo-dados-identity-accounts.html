Especificação integral

Modelo de dadosFundamentos

1. Finalidade, autoridade e escopo

Este documento é normativo para S1-02 e S1-03. Define o modelo mínimo e completo de users, tenants, identity_links e accounts. Não define endpoints, movimentações, conexões Pluggy, auditoria, OpenAPI ou CRUD posterior.

Entradas autoritativas: Documento de Visão 1.3; PRD 1.4, em especial HU-001, HU-002, RN-001 a RN-004 e RNF-002 a RNF-003; Arquitetura 1.5; Plano da Sprint 1, S1-02 e S1-03. Em conflito, prevalecem requisito explícito atual, contrato formal e decisão aprovada, nessa ordem.

2. Fronteiras e terminologia

  • Identity possui users, tenants e identity_links.
  • Accounts possui accounts.
  • Um módulo usa somente a interface pública de Application de outro módulo; não acessa tabela nem repositório interno alheio.
  • Domain e Application não importam Prisma, PostgreSQL, Neon, NestJS, HTTP, Auth0 ou Zod.
  • Tenant é o espaço financeiro exclusivo de uma pessoa. User é a identidade interna. Identity link associa uma identidade autenticada externa ao user interno.

3. Identificadores e cardinalidades

Todas as chaves internas são UUIDv4 em PostgreSQL uuid, geradas pelo banco com gen_random_uuid(). Prisma representa-as como String @db.Uuid; Domain e API usam strings UUID canônicas validadas, preferencialmente encapsuladas em tipos nominais próprios.

  • Um tenant possui exatamente um user e um user pertence exatamente a um tenant.
  • users.tenant_id é obrigatório e único; trigger diferido impede tenant sem user ao final da transação.
  • Um user possui uma ou mais identity links; cada link pertence a exatamente um user.
  • Um tenant possui zero ou mais accounts; cada account pertence a exatamente um tenant.

8. Semântica monetária

  • initial_balance é o saldo líquido da conta no fim da data initial_balance_as_of, antes das movimentações acompanhadas posteriormente.
  • Positivo representa ativo; negativo representa obrigação ou déficit; zero é válido. Tipo de conta não altera essa convenção.
  • Intervalo: −99.999.999.999.999.999,99 a 99.999.999.999.999.999,99.
  • Entrada aceita string decimal canônica com no máximo duas casas. Mais casas são rejeitadas; não há arredondamento implícito na borda.
  • Domain usa Money imutável com amountInCents: bigint e currency: 'BRL'. API recebe e devolve decimal string com duas casas. Nunca usa number binário para persistência ou serialização.
  • A data de referência não pode ser futura em UTC no momento da criação. Alterá-la depois exige revalidação conjunta do saldo.
Modelo de dadosValidação e migrations

9. Validação em profundidade

  • Textos humanos passam por Unicode NFC, trim e colapso de whitespace Unicode interno para um espaço.
  • name: obrigatório, 1–100 caracteres Unicode; institution_name: opcional, 1–120 quando presente. String vazia de instituição vira null.
  • Caracteres de controle e de formatação invisível são rejeitados. Letras, números, acentos, símbolos e emoji visíveis são aceitos.
  • Issuer, subject e IDs externos são opacos: não sofrem lowercase, NFC ou colapso; rejeitam vazio, bordas em branco, NUL/controles e excesso de tamanho.
  • Zod valida somente na borda inbound. O domínio repete as invariantes sem importar Zod. O adapter traduz Prisma/SQLSTATE para erros tipados.
  • Erros mínimos: InvalidAccountName, InvalidInstitution, InvalidAccountType, InvalidMoney, InvalidBalanceReferenceDate, ExternalAccountConflict, IdentityAlreadyLinked, OwnerNotFound e TenantMismatch.

11. Convenções de migration

Migrations usam diretórios Prisma ordenados e nomes descritivos, por exemplo 20260909_identity_accounts_foundation e 20260909_identity_accounts_rls. Gerar com prisma migrate dev --create-only, revisar e acrescentar SQL customizado antes de aplicar. Constraints seguem <tabela>_<colunas>_<tipo>; índices, <tabela>_<colunas>_idx; policies, <tabela>_<comando>_own.

Não editar migration já aplicada. Mudanças futuras seguem forward migration e, quando houver risco de dados, expand/contract. Recuperação usa correção forward ou restore controlado; rollback destrutivo não é presumido. RLS, triggers e checks não expressáveis no Prisma permanecem SQL revisado na mesma história de migrations. db push não substitui migrations versionadas.

enum IdentityProvider {
  AUTH0 @map("auth0")
  @@map("identity_provider")
}

enum AccountOrigin {
  MANUAL @map("manual")
  CONNECTED @map("connected")
  @@map("account_origin")
}

enum AccountExternalProvider {
  PLUGGY @map("pluggy")
  @@map("account_external_provider")
}
enum AccountType {
  CHECKING @map("checking")
  SAVINGS @map("savings")
  PAYMENT @map("payment")
  CASH @map("cash")
  CREDIT_CARD @map("credit_card")
  INVESTMENT @map("investment")
  OTHER @map("other")
  @@map("account_type")
}

model Tenant {
  id String @id @default(dbgenerated("gen_random_uuid()")) @db.Uuid
  createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz(3)
  updatedAt DateTime @default(now()) @updatedAt @map("updated_at") @db.Timestamptz(3)
  user User?
  accounts Account[]
  @@map("tenants")
}

model User {
  id String @id @default(dbgenerated("gen_random_uuid()")) @db.Uuid
  tenantId String @unique(map: "users_tenant_id_key") @map("tenant_id") @db.Uuid
  createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz(3)
  updatedAt DateTime @default(now()) @updatedAt @map("updated_at") @db.Timestamptz(3)
  tenant Tenant @relation(fields: [tenantId], references: [id], onDelete: Cascade, onUpdate: Restrict, map: "users_tenant_id_fkey")
  identityLinks IdentityLink[]
  @@map("users")
}

model IdentityLink {
  id String @id @default(dbgenerated("gen_random_uuid()")) @db.Uuid
  userId String @map("user_id") @db.Uuid
  provider IdentityProvider
  issuer String @db.VarChar(255)
  subject String @db.VarChar(255)
  createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz(3)
  updatedAt DateTime @default(now()) @updatedAt @map("updated_at") @db.Timestamptz(3)
  user User @relation(fields: [userId], references: [id], onDelete: Cascade, onUpdate: Restrict, map: "identity_links_user_id_fkey")
  @@unique([issuer, subject], map: "identity_links_issuer_subject_key")
  @@index([userId], map: "identity_links_user_id_idx")
  @@map("identity_links")
}

model Account {
  id String @id @default(dbgenerated("gen_random_uuid()")) @db.Uuid
  tenantId String @map("tenant_id") @db.Uuid
  name String @db.VarChar(100)
  type AccountType
  origin AccountOrigin @default(MANUAL)
  institutionName String? @map("institution_name") @db.VarChar(120)
  initialBalance Decimal @map("initial_balance") @db.Decimal(19, 2)
  initialBalanceAsOf DateTime @map("initial_balance_as_of") @db.Date
  currencyCode String @default("BRL") @map("currency_code") @db.VarChar(3)
  externalProvider AccountExternalProvider? @map("external_provider")
  externalAccountId String? @map("external_account_id") @db.VarChar(255)
  archivedAt DateTime? @map("archived_at") @db.Timestamptz(3)
  createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz(3)
  updatedAt DateTime @default(now()) @updatedAt @map("updated_at") @db.Timestamptz(3)
  tenant Tenant @relation(fields: [tenantId], references: [id], onDelete: Restrict, onUpdate: Restrict, map: "accounts_tenant_id_fkey")
  @@unique([tenantId, externalProvider, externalAccountId], map: "accounts_external_identity_key")
  @@index([tenantId, archivedAt], map: "accounts_tenant_id_archived_at_idx")
  @@index([tenantId, type], map: "accounts_tenant_id_type_idx")
  @@map("accounts")
}

ALTER TABLE public.accounts
  ADD CONSTRAINT accounts_name_normalized_check CHECK (
    char_length(name) BETWEEN 1 AND 100
    AND name = regexp_replace(btrim(name), '[[:space:]]+', ' ', 'g')
    AND name !~ '[[:cntrl:]]'
  ),
  ADD CONSTRAINT accounts_institution_normalized_check CHECK (
    institution_name IS NULL OR (
      char_length(institution_name) BETWEEN 1 AND 120
      AND institution_name = regexp_replace(btrim(institution_name), '[[:space:]]+', ' ', 'g')
      AND institution_name !~ '[[:cntrl:]]'
    )
  ),
  ADD CONSTRAINT accounts_currency_code_check CHECK (currency_code = 'BRL'),
  ADD CONSTRAINT accounts_origin_external_check CHECK (
    (origin = 'manual' AND external_provider IS NULL AND external_account_id IS NULL)
    OR
    (origin = 'connected' AND external_provider IS NOT NULL
      AND external_account_id IS NOT NULL
      AND char_length(external_account_id) BETWEEN 1 AND 255
      AND external_account_id = btrim(external_account_id)
      AND external_account_id !~ '[[:cntrl:]]')
  );

ALTER TABLE public.identity_links
  ADD CONSTRAINT identity_links_issuer_check CHECK (
    char_length(issuer) BETWEEN 1 AND 255
    AND issuer = btrim(issuer) AND issuer !~ '[[:cntrl:]]'
  ),
  ADD CONSTRAINT identity_links_subject_check CHECK (
    char_length(subject) BETWEEN 1 AND 255
    AND subject = btrim(subject) AND subject !~ '[[:cntrl:]]'

CREATE OR REPLACE FUNCTION public.set_updated_at() RETURNS trigger
LANGUAGE plpgsql AS $$ BEGIN NEW.updated_at := CURRENT_TIMESTAMP; RETURN NEW; END $$;

CREATE TRIGGER tenants_set_updated_at BEFORE UPDATE ON public.tenants
FOR EACH ROW EXECUTE FUNCTION public.set_updated_at();
CREATE TRIGGER users_set_updated_at BEFORE UPDATE ON public.users
FOR EACH ROW EXECUTE FUNCTION public.set_updated_at();
CREATE TRIGGER identity_links_set_updated_at BEFORE UPDATE ON public.identity_links
FOR EACH ROW EXECUTE FUNCTION public.set_updated_at();
CREATE TRIGGER accounts_set_updated_at BEFORE UPDATE ON public.accounts
FOR EACH ROW EXECUTE FUNCTION public.set_updated_at();

CREATE OR REPLACE FUNCTION public.assert_tenant_has_user() RETURNS trigger
LANGUAGE plpgsql AS $$
DECLARE checked_tenant uuid;
BEGIN
  IF TG_TABLE_NAME = 'tenants' THEN
    checked_tenant := NEW.id;
  ELSIF TG_OP = 'DELETE' THEN
    checked_tenant := OLD.tenant_id;
  ELSE
    checked_tenant := OLD.tenant_id;
  END IF;

  IF EXISTS (SELECT 1 FROM public.tenants t WHERE t.id = checked_tenant)
     AND NOT EXISTS (SELECT 1 FROM public.users u WHERE u.tenant_id = checked_tenant) THEN
    RAISE EXCEPTION 'tenant must have exactly one user' USING ERRCODE = '23514';
  END IF;

  IF TG_TABLE_NAME = 'users' AND TG_OP = 'UPDATE'
     AND NEW.tenant_id IS DISTINCT FROM OLD.tenant_id
     AND EXISTS (SELECT 1 FROM public.tenants t WHERE t.id = NEW.tenant_id)
     AND NOT EXISTS (SELECT 1 FROM public.users u WHERE u.tenant_id = NEW.tenant_id) THEN
    RAISE EXCEPTION 'tenant must have exactly one user' USING ERRCODE = '23514';
  END IF;

  RETURN NULL;
END $$;

CREATE CONSTRAINT TRIGGER tenants_require_user
AFTER INSERT OR UPDATE OF id ON public.tenants DEFERRABLE INITIALLY DEFERRED
FOR EACH ROW EXECUTE FUNCTION public.assert_tenant_has_user();
CREATE CONSTRAINT TRIGGER users_preserve_tenant_user
AFTER DELETE OR UPDATE OF tenant_id ON public.users DEFERRABLE INITIALLY DEFERRED
FOR EACH ROW EXECUTE FUNCTION public.assert_tenant_has_user();
Modelo de dadosCasos e decisões

14. Edge cases e resultados

  • Tenant inexistente, owner removido ou relação inconsistente: FK/check falha; adapter devolve OwnerNotFound ou TenantMismatch.
  • Segundo user no mesmo tenant: users_tenant_id_key rejeita. Tenant sem user no commit: trigger diferido rejeita.
  • Tipo inválido, nome vazio, instituição inválida ou origem incoerente: rejeição antes do banco e constraint como defesa.
  • Limites monetários inclusivos são aceitos; overflow é rejeitado. Mais de duas casas é rejeitado na borda/domínio; escrita SQL direta em numeric pode arredondar e é risco residual controlado por privilégios.
  • Exclusão de tenant com account existente: RESTRICT. Exclusão autorizada do tenant após limpeza das accounts: cascade para user e links.
