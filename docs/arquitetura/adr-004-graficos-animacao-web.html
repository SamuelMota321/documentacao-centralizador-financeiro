ADR-004 · Frontend web

Gráficos com visx e animação com Motion

Escalas de uma biblioteca, desenho próprio, e animação em JavaScript só onde o CSS não alcança.

Versão 1.005 nov 2026Status: proposto

Neste documento

ADR integral

ADR Gráficos e AnimaçãoContexto

1. Status, contexto e escopo

Status: proposto em 05/11/2026. Passa a aceito quando a equipe aprovar a branch feat/graficos-animacao do web. Aplica-se aos gráficos do dashboard (HU-010, Sprint 5), à alocação da HU-011 e às animações do app web que o CSS não consegue fazer.

O web não tinha biblioteca de gráficos nem de animação; os gráficos existiam só no mockup "Visão geral" do Style Guide 2.0. O guia fixa um desenho específico (linha de 1,5px, grade tracejada, rampa neutra, sem rosca nem área preenchida), exige os valores em texto ao lado de cada gráfico e proíbe animar números. O ADR-002 rejeitou uma biblioteca de animação JavaScript para a navegação entre páginas; este ADR não muda essa decisão.

2. Evidência técnica

  • motion 14.9.1 e @visx/scale 4.0.0 declaram React 18 e 19 nos peerDependencies (consulta ao npm em 05/11/2026; o web usa React 19.2.8 e Next 16.3.4).
  • O MotionConfig reducedMotion="user" desliga só animações de transform. Altura e posição de elementos SVG não são transform: o código as torna imediatas com useReducedMotion.
  • Medição no build de produção: com domAnimation carregado de forma síncrona no layout raiz, cerca de 27 KB gzip a mais em todas as páginas; com carregamento assíncrono, cerca de 15 KB no carregamento inicial e 19 KB depois da primeira pintura.

3. Alternativas avaliadas

AlternativaResultadoMotivo
SVG próprio sem bibliotecaRejeitadaEscalas, ticks arredondados e bandas reescritos à mão; a transição entre períodos fica sem suporte.
Recharts 3RejeitadaTraz aparência, tooltip e animação próprios; a animação roda a cada montagem, o que contraria o guia.
visx completo (shape, axis, grid, group)RejeitadaEixo, grade e caminho da linha são poucas linhas de SVG; pacotes a mais sem ganho.
GSAPRejeitadaAPI imperativa, distante do modelo de componentes do React.
@visx/scale + MotionAceitaEscalas confiáveis com desenho e estilo próprios; transições de atributos SVG interrompíveis e com movimento reduzido.
ADR Gráficos e AnimaçãoDecisão

4. Decisão

  • Gráficos em src/components/charts/: barras pareadas por mês, linha com pontos, barras horizontais ordenadas e barra 100%. Cada um traz os valores em tabela ou lista; o SVG fica fora da leitura de tela.
  • Valores chegam como string decimal; percentuais são calculados em centavos com BigInt. Número de ponto flutuante só na geometria.
  • Motion via LazyMotion estrito e m.*, com os recursos carregados depois da primeira pintura, dentro de MotionProvider no layout raiz.
  • Motion só onde o CSS não alcança: altura e posição de barras e pontos SVG quando os dados mudam, e a entrada única do gráfico na página inicial. Barras horizontais e barra 100% usam transição CSS e são componentes de servidor.
  • Nada anima na primeira pintura das telas de dados; números em texto nunca animam; a navegação continua com o crossfade do ADR-002.

5. Consequências

  • Duas dependências novas no web, com cerca de 15 KB gzip no carregamento inicial de todas as páginas. Se isso pesar, o provider pode descer para as rotas que usam gráficos.
  • O SVG dos gráficos só monta no navegador, depois de medir a largura; o servidor entrega a tabela com os valores e reserva a altura.
  • Os tokens de movimento passam a existir também em src/lib/motion.ts, espelhando globals.css; mudar um exige mudar o outro.

6. Validação

  • Testes dos cálculos (centavos, percentual com uma casa, geometria) e da renderização no servidor (tabela no HTML, SVG fora da leitura).
  • pnpm lint && pnpm typecheck && pnpm test && pnpm build sem erro.
  • Pendente: verificação no navegador da entrada na página inicial, do destaque gráfico ↔ tabela, do contraste no tema escuro e de prefers-reduced-motion: reduce.
